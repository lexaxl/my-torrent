- (version) UniFFI (mozilla/uniffi-rs) — production-quality Swift bindings generation, actively maintained by Mozilla as of Nov 2025 docs, pre-1.0 but production-used in Firefox. Verified via web search 2026-07-27.
- (version) SwiftUI MenuBarExtra requires macOS 13 (Ventura)+ — compatible with Product Brief's 'last 1-2 macOS versions' Apple Silicon-only target. Verified via web search 2026-07-27.
- (decision) AD candidate: single-process embedded architecture — Rust engine compiled as a library, linked in-process into the native macOS app via UniFFI. Rejected: separate daemon/XPC process (resource overhead conflicts with near-zero-idle requirement, signing friction conflicts with $0/unsigned distribution) and sidecar-over-socket. User confirmed.
- (version) librqbit — actively maintained Rust BitTorrent library (docs updated June 2026), built on tokio, full-featured (backbone of rqbit client). Verified via web search 2026-07-27.
- (version) tokio — dominant async Rust runtime in 2026, current LTS 1.47.x (until Sep 2026) / 1.51.x (until Mar 2027). Verified via web search 2026-07-27.
- (decision) AD candidate: BitTorrent protocol layer built on librqbit (tokio-based), not a from-scratch protocol implementation. Directly resolves the Product Brief's flagged timeline-vs-quality tension for the 1-week v1 target. User confirmed.
- (decision) AD candidate: UI framework = SwiftUI throughout (main window, torrent detail, settings, MenuBarExtra for menu-bar layer), not AppKit. Fits beginner skill level (less boilerplate) and v1 scale (handful of torrents, no NSTableView virtualization need). User confirmed.
- (decision) AD candidate: Swift UI polls Rust core via a synchronous UniFFI snapshot function on a ~1s timer (pull model), not push/callback interfaces. Chosen for simplicity on a first Rust+Swift bridge project over marginal efficiency gains from push. User confirmed.
- (decision) AD candidate: split state ownership. Rust/librqbit owns torrent session state (its own resume-data mechanism). Swift owns app settings (default save path, default seed duration) via native UserDefaults. Boundary is one-directional: Swift passes settings values into Rust as call parameters when adding a torrent; Rust never reads Swift preferences directly. User confirmed.
- (decision) AD candidate: FFI errors use UniFFI's typed Result<T, Error> -> Swift throws mapping throughout, not string/code-based error signaling.
- (decision) AD candidate: all UniFFI calls invoked off the main thread (background Task/actor); results marshaled back to MainActor for UI updates. Prevents blocking Rust I/O from stalling SwiftUI. User confirmed both.
- (decision) AD candidate: build/distribution via GitHub Actions CI triggered on tag, producing an unsigned .dmg published to GitHub Releases. No cloud infra/backend — purely local desktop app. Covers the deployment/operational envelope dimension.
- (decision) Reconciliation fix (Finalize step 2): AD-4 polling refined to run only while >=1 torrent is active (not always-on) — resolves conflict with near-zero-idle success criterion while still supporting completion notifications/menu-bar accuracy without an open window.
