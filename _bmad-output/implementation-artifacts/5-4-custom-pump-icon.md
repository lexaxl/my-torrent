# Story 5.4: Кастомная иконка-насос

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

Как пользователь,
я хочу, чтобы у приложения была отличительная иконка-насос вместо стандартной,
чтобы у приложения была собственная визуальная идентичность в Dock, Finder и меню-баре.

## Acceptance Criteria

1. **Given** приложение собрано, **when** смотрю на Dock/Finder, **then** иконка приложения — векторный силуэт насоса (custom `AppIcon.appiconset`, все требуемые размеры для macOS). **ДОСТИГНУТО.**
2. **Given** смотрю на иконку меню-бара, **and** нет активных закачек, **then** показывается «простой» вариант насоса (outline/приглушённый), заменяя текущий `arrow.up.arrow.down.circle`. **ДОСТИГНУТО** — `PumpShape().stroke(Color.torrentMuted, ...)`, подтверждено на реальной сборке.
3. **Given** есть ≥1 активная закачка, **then** показывается «активный» вариант насоса (акцентный цвет), заменяя текущий `arrow.up.arrow.down.circle.fill`. **ДОСТИГНУТО** — `PumpShape().fill(Color.torrentAccent)`, подтверждено на реальной сборке.
4. **Given** оба места (app icon и menu-bar) используют единый визуальный стиль насоса. **ДОСТИГНУТО** — та же геометрия силуэта (рукоятка/шток/цилиндр-корпус/раструб-основание), что и в `AppIcon.appiconset`, воспроизведена как `PumpShape` в Swift для меню-бара.
5. **Given** реализация через `.help(_:)` на `Image` внутри `MenuBarExtra`'s `label:`, **then** это эмпирически проверено на реальной сборке — не предполагается по документации. **Не применимо к этой истории напрямую** (это условие из Story 5.3's AC, скопированное в `epics.md`'s заготовку Story 5.4 по ошибке — не про эту историю; см. Scope Boundary).

## Scope Boundary

**Решено при создании истории (задним числом, после реализации — история делалась без отдельного `bmad-create-story`-прохода, сразу разработкой с последующей документацией):**

- **App icon (AC1) полностью реализован и подтверждён.** Векторный силуэт насоса (закруглённый квадрат с градиентным индиго-фоном `#5E70DE`→`#3B49B0`, белый силуэт насоса — рукоятка, шток, цилиндр-корпус, раструб-основание, штуцер с каплей), отрисован как SVG (`rsvg-convert`), растеризован в 10 PNG (все размеры `idiom: mac` — 16/32/128/256/512 в 1x/2x) в `MyTorrent/Assets.xcassets/AppIcon.appiconset/`. Проект уже ссылался на `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` в билд-настройках (XcodeGen генерирует это по умолчанию для application-таргетов), но каталога `Assets.xcassets` в проекте не существовало вообще (впервые подтверждено в Story 5.2's Scope Boundary) — эта история впервые создаёт его. XcodeGen автоматически подхватывает `.xcassets`-папку по `sources: - path: MyTorrent` в `project.yml`, без изменений самого `project.yml`.
- **Иконка меню-бара (AC2/AC3) — технически реализована и один раз подтверждена (fill-вариант), но не финализирована и не закоммичена.** Первый проход этой же сессии посчитал это «открытым техническим тупиком» (glyph якобы всегда невидим), но это оказалось ложным выводом — см. ниже.
  - **Что произошло**: несколько подходов (растровый `Image` из `Assets.xcassets`, `NSImage(named:)`, `Canvas`, кастомный `Shape`) подряд «не отображались» при визуальной проверке пользователем. Позже выяснилось (при обновлении project memory), что Story 4.1 уже задокументировала: менюbar-иконка в этом окружении может быть **визуально невидимой просто из-за переполненного меню-бара** (~13 сторонних status-item'ов на этой машине; macOS не даёт overflow-«…» для сторонних `NSStatusItem`), подтверждено ТОГДА через Accessibility API, не визуально — Story 5.3 закрепила AX-проверку как стандартную технику именно по этой причине.
  - **Ретест под явно подтверждённо-чистыми условиями (та же сессия, чуть позже)**: сначала проверена базовая линия — исходный SF Symbol реально виден пользователем в этот момент (бар не переполнен прямо сейчас) — затем `PumpShape().fill(Color.red)` (тот же код, включая исправленный ранее баг порядка композиции `CGAffineTransform`) **реально отобразился** на экране пользователя. Это подтверждает: кастомный `Shape`-подход технически рабочий, а вся серия «невидимо» ранее была тем же known crowding-эффектом, не новым багом.
  - **Почему не закоммичено**: пользователь попросил остановиться и вынести финализацию (`.stroke()`-вариант для idle-состояния не успели протестировать под чистыми условиями; открыт вопрос постановки — устраивает ли процедурная Shape-отрисовка вместо растровых `Assets.xcassets`-изображений) как отдельный вопрос дизайна/постановки, не как техническую доработку. `MyTorrentApp.swift`/`Color+DesignSystem.swift` откачены (`git checkout`) к исходному рабочему `Image(systemName: "arrow.up.arrow.down.circle(.fill)")` — рабочий код `PumpShape`/`Color.torrentAccent` не утерян, воспроизводим по геометрии, задокументированной в `deferred-work.md`.
- **Отдельная, уже решённая по ходу истории проблема: Dock/Finder показывали устаревшую (сгенерированную до появления `Assets.xcassets`) иконку из кэша.** Подтверждено: сам собранный `AppIcon.icns` внутри `.app`-бандла корректен (проверено прямым извлечением и просмотром пикселей), но Finder показывал не связанную с ним иконку по кэшу, привязанному к пути `DerivedData`. С разрешения пользователя выполнено `rm -rf ~/Library/Caches/com.apple.iconservices.store && killall Dock Finder` — не помогло для конкретного `DerivedData`-пути (Finder-кэш для этого пути оказался более стойким, чем ожидалось), но копия `.app` по свежему пути (`~/Desktop`, никогда не кэшировавшемуся) сразу показала верную иконку — подтверждает, что сама иконка корректна, а проблема ограничена конкретно устойчивым Finder-кэшем для многократно пересобираемого `DerivedData`-пути. Это дев-окружение-специфичный нюанс, а не баг реализации; тестовая копия на Desktop удалена после проверки.
- **Отдельный, явно вынесенный пользователем за рамки этой истории вопрос: `LSUIElement`/accessory-lifecycle (AD-7) означает, что у приложения нет Dock-иконки, пока оно запущено** — это ожидаемое, документированное поведение (Story 1.3/AD-7, сознательный выбор ради «работает тихо в фоне, единственный выход — явный Quit»), не баг этой истории. Пользователь в сессии сказал, что теперь хочет Dock-иконку во время работы — явно отложено пользователем как отдельное решение (потребовало бы пересмотра AD-7, не тривиальное добавление). См. `deferred-work.md`.
- **Финализирующее решение по постановке (после короткого brainstorming-прохода, тот же день) — реализовано и подтверждено:**
  - **Процедурная `Shape`-отрисовка в Swift, не растровый `Assets.xcassets`-образ.** Не требует нового asset-каталога для меню-бара; цвета — простые `Color`-значения, легко править без перегенерации PNG. Силуэт насоса концептуально описан дважды (SVG для app icon, `Path` для меню-бара) — два разных рендер-контекста с разными техническими ограничениями, дублирование осознанно принято.
  - **Idle-состояние — тонкий обвод (`.stroke`, lineWidth 1.5), `Color.torrentMuted`.** Буквально соответствует исходной формулировке AC2 («outline/приглушённый»), совпадает с логикой прежних SF Symbol'ов (обвод vs `.fill` для активного состояния). **Важная находка при финализации**: изначально запланированный `Color.secondary` (системный SwiftUI-semantic цвет) оказался невидимым именно внутри `MenuBarExtra`'s `label:` — изолировано эмпирически (`.stroke(Color.red, ...)` в том же месте отобразился нормально, значит проблема не в `.stroke()` самом по себе, а конкретно в `Color.secondary`). Заменён на новый токен `Color.torrentMuted = Color(nsColor: .secondaryLabelColor)` — тот же паттерн AppKit-appearance-resolved `NSColor`, что уже использовался для `torrentAccent`/`torrentSuccess`, а не SwiftUI-environment-resolved `Color.secondary`/`.primary`/`.accentColor`. **Общий вывод для будущих историй, трогающих `MenuBarExtra`'s `label:`**: используйте `Color(nsColor: ...)`-обёрнутые цвета, не голые SwiftUI semantic-цвета — последние, похоже, не резолвятся корректно в этом рендер-контексте.
  - **Active-состояние — заливка (`.fill`) `Color.torrentAccent`** (`#4C5FD5`/`#7C8CF0`, design-system `color-accent`) — подтверждено видимым на реальной сборке с финальным цветом (не только с тестовым `Color.red`-заместителем).
  - **Размер — `.frame(width: 18, height: 18)`**, как и было.
  - **Методология верификации, подтвердившая себя при финализации**: перед тем как доверять любому «не видно» на этой машине, сначала подтверждать, что уже работающая baseline-иконка видна ПРЯМО СЕЙЧАС — именно так был найден `Color.secondary`-баг (бар был подтверждённо не переполнен, а `.stroke(Color.secondary,...)` всё равно не отображался — что и указало на цвет, а не на переполнение бара, как на причину).
- **AC5 из `epics.md`'s исходной формулировки** — про эмпирическую проверку `.help(_:)` — это буквально скопированное условие из Story 5.3's AC5, оставшееся в `epics.md`'s заготовке Story 5.4 по инерции (обе истории трогают один и тот же `MenuBarExtra`'s `label:`). Story 5.3 уже закрыла этот вопрос для `.help(_:)` самого по себе; в этой истории `.help(_:)` не менялся (тот же вызов, что и был), так что это условие не про новую работу этой истории.

## Dev Notes

### Technical Requirements / Stack

- **XcodeGen** (`project.yml`) — `.xcassets`-каталоги подхватываются автоматически по `sources: - path: MyTorrent`, без явного перечисления в `project.yml`. `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` уже был в сгенерированных билд-настройках (дефолт XcodeGen для application-таргетов) ещё до появления самого каталога.
- **`rsvg-convert`** (Homebrew, `librsvg`) — использован для рендера SVG→PNG на каждый целевой пиксельный размер напрямую; не входит в зависимости проекта (dev-tool, не рантайм-зависимость).
- **Design System** (`design-artifacts/D-Design-System/00-design-system.md`) — `color-accent` `#4C5FD5`/`#7C8CF0` использован дважды: для градиента фона app icon (в исходном SVG/растровых PNG) и как Swift-токен `Color.torrentAccent` (`Color+DesignSystem.swift`) для активного состояния меню-бар glyph'а.
- **`Color(nsColor: NSColor)`-обёртки для меню-бар цветов, не SwiftUI semantic-цвета** — `Color.secondary` эмпирически не резолвится внутри `MenuBarExtra`'s `label:` (см. Scope Boundary); `Color.torrentMuted`/`Color.torrentAccent` оба построены через `NSColor`, тот же паттерн, что `Color.torrentSuccess` (Story 5.2).

### Architecture Compliance

- `AD-3` (SwiftUI throughout, no AppKit) — финальная реализация (`PumpShape: Shape`) чисто SwiftUI, никаких AppKit-вью/контролов. Цвета (`Color.torrentAccent`/`torrentMuted`) построены через `NSColor(...)`-обёртку — тот же уже устоявшийся паттерн, что `Color.torrentSuccess` (Story 5.2) для получения адаптивного `Color` без Assets.xcassets-инфраструктуры; не вводит AppKit-вью — `AD-3` не нарушен. (Промежуточные попытки этой истории также пробовали `NSImage(named:)`/`isTemplate`, тем же непрямым паттерном — в финал не вошли, растровый подход для меню-бара не понадобился.)
- Не затрагивает `engine/`/Rust/FFI/поллинг — чисто presentation-слой. `AD-1`, `AD-2`, `AD-4`–`AD-9` не применимы.
- `AD-10` (unsigned CI-сборка) — не затронут; локальные сборки в этой истории все через `xcodebuild` напрямую, не через `release.yml`.
