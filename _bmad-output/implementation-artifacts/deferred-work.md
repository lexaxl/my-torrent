## Deferred from: Story 5.4 (кастомная иконка-насос, 2026-07-30)

- **Кастомный пользовательский glyph (не SF Symbol) не отображается в иконке меню-бара `MenuBarExtra`** [MyTorrent/MyTorrentApp.swift, `MenuBarExtra`'s `label:`] — эмпирически подтверждено на реальной сборке (не предположение по документации): элемент статус-бара реально создаётся и кликабелен (подтверждено через Accessibility API — присутствует в дереве, корректная геометрия, клик открывает popover), но сам glyph рендерится полностью невидимым, независимо от подхода:
  - `Image("AssetName")` из `Assets.xcassets` (template и non-template через `template-rendering-intent: original` в Contents.json) — невидимо.
  - `.renderingMode(.original)` на том же `Image` — невидимо.
  - `NSImage(named:)` с явным `isTemplate = false`, обёрнутый в `Image(nsImage:)` — невидимо.
  - `Canvas` с ручной отрисовкой `Path` — невидимо.
  - Кастомный `Shape`-конформер (`.fill()`/`.stroke()`) — тоже невидимо в финальном тесте (даже в самом минимальном виде, без `Group`/условной ветки).
  - Единственное, что реально отобразилось в этой сессии — примитивный `Circle().fill(Color.red)` без всякой кастомной геометрии; поэтому природа бага не полностью изолирована (не проверено: баг ли это конкретно в геометрии `PumpShape`, в способе, которым `MenuBarExtra` конвертирует произвольный SwiftUI-view в `NSStatusItem`-изображение, или что-то специфичное для этой машины/версии macOS/Xcode — `assetutil` показывал `AssetStorageVersion: Xcode 26.4 (17E192)`, нетипично новая версия для существующих знаний о поведении AppKit/SwiftUI).
  - Кэш иконок (`~/Library/Caches/com.apple.iconservices.store` + `killall Dock Finder`) **не** влияет на этот баг — это отдельная, уже решённая проблема (см. ниже), затрагивавшая только Dock/Finder-иконку `.app`-бандла, не `NSStatusItem`.
  - **Важный контекст, найденный только после отката (в project memory, не был перепроверен во время самой сессии)**: Story 4.1 уже задокументировала, что менюbar-иконка в этом окружении может быть **визуально невидимой просто из-за переполненного меню-бара** (~13 сторонних status-item'ов на этой машине; macOS не даёt overflow-«…» для сторонних `NSStatusItem`/`MenuBarExtra`, в отличие от Control Center) — подтверждено ТОГДА через Accessibility API (элемент существует, верный a11y-label), не через скриншот/визуальный осмотр. Story 5.3 закрепила это как стандартную технику: проверять `help`-атрибут через AX, а не глазами/скриншотом. **В этой сессии визуальная проверка (глазами пользователя, не через AX) была основным методом** — это могло дать ложно-отрицательный результат по той же причине, что уже была известна с Story 4.1, а не обязательно означает, что кастомный `Shape`/`Image`/`Canvas` рендерится некорректно. Разовый успех `Circle().fill(Color.red)` мог быть совпадением по времени (сразу после `killall Dock`, когда бар мог быть временно менее заполнен). **Прежде чем возобновлять эту работу**: сначала проверить через AX (`value`/`help`/`position`/`size` элемента), не полагаться только на то, видит ли иконку пользователь глазами — возможно, кастомный glyph работает корректно и это тот же уже известный per-machine crowding-эффект, а не новый баг.
  - **Текущее состояние**: `MyTorrentApp.swift` откачен к исходному `Image(systemName: "arrow.up.arrow.down.circle(.fill)")` — рабочему SF Symbol-варианту из Story 4.1/5.3. AC2/AC3 Story 5.4 (простой/активный вариант насоса в меню-баре) **не выполнены** — это открытый пробел, а не тихо принятый компромисс.
  - **Куда копать дальше**: (1) проверить, не баг ли специфичный для этой версии macOS/Xcode (`Xcode 26.4`/`17E192`) — воспроизвести на другой машине/более стабильной версии; (2) изолировать, действительно ли именно кастомная геометрия `PumpShape` — протестировать встроенный `RoundedRectangle`/`Capsule` (не `Circle`) с кастомным цветом, чтобы исключить версию «только `Circle` работает, любой другой `Shape` — нет»; (3) проверить `MenuBarExtra`'s `.menuBarExtraStyle(.menu)` (не `.window`) — вдруг эффект specific к `.window`-стилю.
- **`LSUIElement`/accessory-lifecycle (AD-7) вызывает вопрос об отсутствии Dock-иконки во время работы приложения** — это ожидаемое, документированное поведение (Story 1.3/AD-7 сознательно выбраны ради "работает тихо в фоне, единственный выход — явный Quit"), не баг. Пользователь в этой сессии сказал, что теперь **хочет** Dock-иконку — явно отложено пользователем как отдельное решение вне скоупа Story 5.4 (потребует пересмотра AD-7: `applicationShouldTerminateAfterLastWindowClosed`, обработчик клика по Dock-иконке для реактивации главного окна, и т.д. — не тривиальное добавление, а разворот архитектурного решения).
