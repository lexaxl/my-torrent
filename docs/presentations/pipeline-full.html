Продукт

my-torrent: тихий клиент, который не мешает

Минималистичная качалка для macOS: .torrent или magnet открывается без единого диалога, живой список закачек, окно деталей с файлами/трекерами/пирами, иконка в меню-баре, уведомление о завершении. Двуязычный интерфейс (ru/en).

  • 15 функциональных требований, каждое привязано к эпику картой покрытия.
  • NFR1 — почти нулевой расход ресурсов в простое. Главная и непереговариваемая метрика: поллинг вообще выключается, когда нет активных торрентов.
  • Только Apple Silicon, только последние версии macOS, распространение неподписанным .dmg — бюджет проекта $0.

Фишка 1

Architecture Spine: инварианты, а не описание

Спина не пересказывает систему — она запрещает. Каждое решение записано тремя полями, и среднее из них самое ценное.

binds

Что связывает

Область, на которую распространяется правило: engine/, граница FFI, весь проект.

prevents

Что предотвращает

Конкретная ошибка, которую разработчик совершил бы по умолчанию, не зная контекста.

rule

Правило

Проверяемая формулировка, на которую можно сослаться в истории и в ревью.

AD-4 предотвращает: «постоянно работающий таймер, противоречащий критерию нулевого простоя; холодный старт, при котором никто не опрашивает движок, потому что никто ещё не знает об активных торрентах».

Прогноз AD-4 сбылся буквально: bootstrap-опрос, заложенный ради холодного старта в эпике 1, через три дня без единой правки подхватил торренты, восстановленные из сессии в эпике 6.

Фишка 2

История — это самодостаточный пакет контекста

Разработчик-агент стартует с чистой памятью. Поэтому файл истории содержит не «что сделать», а всё, что нужно, чтобы сделать это правильно с первого раза.

Фишка 3

Dev Agent Record: отчёт, где отклонения записаны честно

После реализации агент дописывает в тот же файл, что реально произошло. Ценность не в галочках, а в местах, где план разошёлся с реальностью.

  • Debug Log. «Контекстное меню SwiftUI-строки недостижимо через Accessibility API — строки расплющены до статик-текстов». Два пункта чек-листа выполнены иначе, чем написано, и это зафиксировано прямым текстом.
  • Completion Notes. Построчно по каждому критерию: подтверждено на живом приложении / покрыто тестом / покрыто механикой библиотеки без отдельной проверки.
  • File List. Точный список тронутых файлов с пометкой характера правки — вплоть до «изменён только комментарий».
«Порядок строк при ≥2 торрентах в UI не проверялся — второго тестового торрента нет. Стабильность id покрыта ассертом в roundtrip-тесте.»

Признание непроверенного — это не слабость отчёта, а его главная функция. Именно эти строчки потом попадают в реестр отложенного и в ретроспективу.

Фишка 4

Адверсариальное код-ревью после каждой истории

Отдельный проход из независимых «охотников» под разными углами, каждая находка потом верифицируется на попытку опровержения. Слабые гипотезы отсеиваются до того, как дойдут до человека.

confirmed · high Повреждённый store делал приложение незапускаемым. Одна битая запись в session.json → ошибка инициализации → fatalError на каждом старте. Crash-loop, из которого пользователь не выберется без ручного удаления папки. Починено карантином store и повторным открытием пустой сессии.
confirmed · med Диалог выхода врал пользователю. Обещал «закачки продолжатся при следующем запуске», хотя нерезолвнутый magnet живёт только в памяти и не переживает выход.
refuted Опровергнутые находки тоже записываются. «fastresume ломается на перемещённых файлах» — нет, librqbit перехеширует. Помечено «окончательно, не переоткрывать»: следующая сессия не потратит время заново.

Оба подтверждённых бага — failure-modes, невидимые на happy-path. Ретроспектива эпика 6 превратила это в action item: для фич, трогающих файлы и сторы, продумывать повреждение и отсутствие данных при реализации, а не на ревью.

Фишки 5 и 6

Долг с адресом и архитектура, которую переписывают

Реестр отложенного

Единый deferred-work.md: каждая запись — что отложено, почему это допустимо сейчас и при каком условии пересмотреть. Закрытие идёт зачёркиванием со ссылкой на историю, исходный текст сохраняется под катом. Один протокол расследования (невидимая иконка в меню-баре) остался в файле целиком — и через две истории сэкономил повторное расследование того же тупика.

  • Отсутствие persistence → закрыто историей 6.2
  • Отсутствие Dock-иконки → закрыто историей 6.1
  • Невоспроизводимый крэш на старте → осознанно оставлен открытым

Живая спина

История 6.1 отменила исходное решение AD-7 (приложение-невидимка без иконки в Dock). Спина не выброшена и не переписана задним числом — решение помечено [ADOPTED; revised 2026-07-30, Story 6.1], ядро правила сохранено, причина пересмотра записана рядом.

Архитектурный документ, который нельзя изменить, перестаёт описывать систему через две недели. Тот, который меняют без следа, перестаёт быть аргументом.
Итог

Что подход дал и чего он стоил

Дал

  • Роадмап из 6 эпиков закрыт за 5 дней, без переписываний архитектуры.
  • Ревью поймало два бага, которые проявились бы только у пользователя.
  • Решения переживают границы сессий: агент читает контекст, а не вспоминает его.
  • Спорные развилки уходили человеку выбором из вариантов, а не угадывались.

Стоил

  • Спеки в 2,7 раза объёмнее кода — на проекте меньшего масштаба это чистые накладные расходы.
  • Ритуал приходится адаптировать: PRD, trigger map и тест-модуль пропущены осознанно.
  • Верификация нативного UI осталась ручной — Accessibility API достаёт не до всего, автотестов Swift нет.
  • Реализация думает про happy-path; failure-modes всплывают только на ревью.

Главный вывод: ценность харнеса не в персонах и не в шаблонах, а в том, что каждое решение получает адрес — файл, строку и причину, на которые можно сослаться через неделю и через сто коммитов.
